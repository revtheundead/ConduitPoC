# conduit Library Documentation

[Back to top-level documentation](../index.md)

conduit is the C++23 runtime library that powers protocol communication. It provides error handling, bit-level I/O, network transports, stream framing, and the `Transceiver` orchestrator that connects generated protocol sessions to real-world I/O -- letting you send and receive typed messages without touching raw bytes.

While the core runtime is written in C++, **Java and Python users** can access Conduit's full capabilities through native bindings:
- **Java:** JNI bindings (Java 8--17) and Panama FFI bindings (Java 21+) at `conduit/bindings/java/`
- **Python:** ctypes-based bindings at `conduit/bindings/python/`

Additionally, the bgen code generator produces standalone codec code in Java and Python that can be used independently of the C++ runtime for encode/decode operations. See the [bgen documentation](../bgen/index.md) for details on multi-language code generation.

## Terminology

| Term | Meaning |
|------|---------|
| **Frame** | The outermost wire-level structure, defined by `<frame>`. Contains header fields, a payload, and optional footer fields. |
| **Message** | A user-facing protocol entity, declared with `<message id="...">` and dispatched by the frame's ID field. |
| **Struct** | A reusable data container (`<struct>`). Structs compose to build messages and frames. |
| **Leaf Type** | A concrete message type reachable from a frame that users send/receive. Each leaf has a `TYPE_ID` and `TYPE_NAME`. |
| **Session** | A stateful encoder/decoder implementing `ISession`. Maps between wire bytes and typed messages. Generated by bgen. |
| **Peer** | A named communication endpoint in the Transceiver, with its own session instance and transport. |

## Layer Architecture

```
┌─────────────────────────────────────────────┐
│              Transceiver                    │  Orchestrates peers, handlers, dispatch
├──────────┬──────────┬───────────────────────┤
│ Handlers │  Queue   │     StreamFramer      │  Message dispatch, back-pressure, framing
├──────────┴──────────┴───────────────────────┤
│              Transports                     │  TCP client/server, UDP, Serial
├─────────────────────────────────────────────┤
│          Sessions / Codec Traits            │  ISession, Encodable, Decodable, Message
├──────────────────┬──────────────────────────┤
│    BitReader     │     BitWriter            │  Bit/byte-level encode/decode
├──────────────────┴──────────────────────────┤
│            Core (Error, Types)              │  ErrorCode, Result<T>, VoidResult
└─────────────────────────────────────────────┘
```

## Namespace Map

| Namespace | Purpose |
|-----------|---------|
| `conduit` | Core types: `Error`, `ErrorCode`, `Result<T>`, `VoidResult`, `Timestamp`, `SteadyTimestamp`, `Duration`, `byte_t` |
| `conduit::io` | `BitReader`, `BitWriter`, `Endian`, byte-swap utilities |
| `conduit::traits` | `ISession`, `DecodedMessage`, `EncodeResult`, `Encodable`, `Decodable`, `Message` concepts |
| `conduit::transceiver` | `Transceiver`, `TransceiverConfig`, `TransceiverStats`, `PeerId`, `InboundMessage`, `MessageHandler`, `HandlerRegistry`, `ErasedHandler`, `StreamFramer`, `CallbackId`, `ErrorEvent`, `ErrorCallback`, `ConnectionStateCallback` |
| `conduit::transceiver::transport` | `ITransport`, `TcpClientTransport`, `TcpServerTransport`, `UdpTransport`, `SerialTransport` |
| `conduit::net` | `ConnectionState` enum |
| `conduit::queue` | `BoundedQueue<T>`, `DropPolicy`, `QueueStats` |
| `conduit::string` | `Encoding` enum, `to_ascii()`, `from_ascii()` |
| `conduit::logging` | `Logger`, `Level`, `ConsoleSink`, `FileSink`, `CategoryLogger`, macros |

## Umbrella Header

```cpp
#include <conduit/conduit.hpp>
```

This pulls in all conduit headers except `<conduit/string/encoding.hpp>` (which is rarely needed directly -- generated code calls it automatically). For fine-grained control, include individual headers (e.g., `<conduit/core/error.hpp>`).
